# Internationalization (i18n) — Meridian Policy Twin

Lightweight, dependency-free i18n for the web app. Four language packs ship
with the build: **English (en)**, **Hausa (ha)**, **Yorùbá (yo)**, **Igbo
(ig)**. English is the source of truth; every other pack must satisfy the
TypeScript `Dict` shape generated from `src/i18n/en.ts`, so a missing or
mis-named key is a compile error, not a runtime fallback.

## Layout of the packs

```
src/i18n/
├── en.ts        # source dictionary + `Dict` type (Widen<typeof en>)
├── ha.ts        # Hausa      (const ha: Dict = {…})
├── yo.ts        # Yorùbá     (const yo: Dict = {…})
├── ig.ts        # Igbo       (const ig: Dict = {…})
└── index.ts     # LocaleCode, LOCALES, getDict()
```

Keys are **namespaced by surface** (`nav`, `layout`, `dashboard`,
`opportunities`, `filter`, `evidence`, `legislation`, `simulation`, `briefs`,
`dataHealth`, `copilot`, `innovations`, `login`, `action`, `status`,
`provenance`, `onboarding`, `common`) and kept flat inside each namespace.
Each pack currently holds **~380 translated strings** (leaf keys; verify with
`grep -c ":\s*\"" src/i18n/<pack>.ts`).

Runtime wiring:

- `src/lib/LocaleContext.tsx` — `LocaleProvider` (mounted in `src/main.tsx`,
  persists to `localStorage["meridian.locale"]`, sets `<html lang>`),
  `useT()` returns the active typed dictionary.
- `src/components/innovations/LanguageSwitcher.tsx` — the EN/HA/YO/IG picker
  in the topbar.
- Placeholders use `{name}` and are interpolated at the call site:
  `t.opportunities.subtitle.replace("{count}", String(n))`.

Engine names, job IDs, request IDs and dates stay in English mono by design
(they are identifiers, not prose). Dynamic strings produced by the API
(sector names, brief titles, law titles) are content, not chrome, and are not
translated client-side.

## How to add a language

1. Copy `src/i18n/en.ts` to `src/i18n/<code>.ts`, change the export name and
   translate every string. Keep the `Dict` type annotation — `tsc` will list
   any key you missed.
2. Register it in `src/i18n/index.ts`: add the code to `LocaleCode`, append
   `{ code, label, nativeLabel }` to `LOCALES`, and add it to `DICTS`.
3. Add the code to the `initialLocale()` allow-list in
   `src/lib/LocaleContext.tsx` (and the switcher shows it automatically via
   `LOCALES`).
4. Run `npx tsc -b` (shape check) and `npm run build`.

## RTL note

All four shipped languages are left-to-right; the app sets `dir` implicitly
(default LTR) and only sets `<html lang>`. If an RTL language (e.g. Arabic,
Fulfulde Ajami) is added: set `document.documentElement.dir = "rtl"` alongside
`lang` in `LocaleContext`, prefer logical CSS properties
(`margin-inline-start`, `padding-inline-end`) over `ml-*/mr-*` utilities in
new components, and re-audit the three-pane workbench layouts (Legislation,
Copilot) whose pane order is meaningful in RTL. The icon set (lucide) is
direction-neutral except arrow affordances in `InnovationPage` and pagination
controls, which should be mirrored.
